# Evidence restoration review

Scope: the 11 restored `kernel/src/fs/rnvpc/*.rs` files, all four provenance notes, and their joins to retained `frame.rs`, `persist.rs`, `wal.rs`, and extent/write-transaction contracts. Read-only source review; only this report was written. Full compile and runtime validation belong to the integration run. This is a reconstruction-candidate review, not approval of a complete research kernel. Missing historical EXT4/PageCache versions remain outside this restoration.

## Reconstruction findings corrected during review

**HIGH — corrected: incomplete legacy WAL accounting assembly.** Initial `cow.rs` called undefined `charge_wal_delta`/`release_wal_delta` and omitted the completion release. The logic owner restored both helpers (`cow.rs:540`, `:554`) and the release call (`:413`) using earlier intact session evidence, documented in `logic-provenance.md`. Re-review confirms the chain now matches retained `wal_pages_for`, `wal.pending`, and `frame::{charge_wal_pages,release_wal_pages}`: charge the rounded incremental page count before append, then recompute/release after retirement. This closes the identified reconstruction omission; it does not establish error-path or concurrency correctness of the inherited algorithm.

**HIGH — corrected: historical test/API version mismatches.** The reservation test at `tests.rs:362` now exactly matches the complete body in raw `bfcc70a3…00086344.txt` (verified by text comparison), imports/constructs `ExtentMutation`, supplies it to all four reserve/consume calls, and retains the stronger one-in-place-record assertion. These calls match retained `write_transaction.rs:590` and `:629`. The later leaf-mutator test depends on `lock_metadata_mutation`, absent from retained `frame.rs`; its complete body is preserved in `docs/recovery/later-tests/metadata_mutation_guard.rs.reference`, outside the compiled module, with the API/version gap explicitly documented. No dummy production API or weakened assertion was introduced. Exactly 25 top-level `#[ktest]` declarations remain. This resolves the identified test assembly mismatches, not the missing later-version behavioral coverage. Final ktest typecheck remains the parent integration run's responsibility; “compiled subset” in provenance describes inclusion in that build, not a successful compile or runtime result.

## Unresolved inherited findings

1. **HIGH — distinct-version duplicate fixed roots are silently accepted.** `recover.rs:116` rejects duplicate `(key, version)` only. Two committed inode descriptors sharing the fixed key but having different versions pass; retained `frame.rs:424` selects the highest version. `recover.rs:202` traces only that selected root, and `recover.rs:482` subsequently reclaims unreachable metadata/data, including the discarded root's graph. This contradicts the retained fixed-root invariant documented at `frame.rs:2038` that multiple fixed roots are corruption. Confidence: high from the control flow; no runtime reproducer run. Classification: inherited recovered scan/retained-frame interaction, not an invented restoration seam. Follow-up should reject duplicate fixed keys before any repair/reclamation and cover distinct-version roots in crash-image tests; preserve the evidence copy and label any hardening separately.

2. **HIGH — legacy completion loses pending reclamation records on an error.** `cow.rs:381` retires WAL before reclaim; `:394` drains the entire pending vector and `:401`–`:403` propagate eviction/clear/free errors. For example, a pinned old page makes eviction fail; returning drops the drain and remaining records, also discards earlier `keep` entries, and bypasses the WAL-capacity release at `:413`. Committed old pages can become permanently untracked and charged WAL capacity remains stranded. Confidence: high from Rust drain/error control flow. Classification: inherited legacy completion behavior, not introduced by the restored helper correction. A separate repair should retain retryable pending entries and reconcile retired-WAL accounting on every exit, with an error-injection test.

3. **MEDIUM — extend-only statistics report zero.** `mod.rs:375` returns immediately when `COW_CONTEXTS` was never initialized, before consulting `EXTEND_CONTEXTS`. An extend-only workload therefore loses its context/counter/residency report. Confidence: high. Classification: inherited and already honestly documented in `entry-tests-provenance.md`. Follow-up should aggregate the two optional tables independently and test extend-only initialization; do not interpret current zero counters as proof that no extend work occurred.

## Contract and provenance assessment

- No empty implementations or compilation-disabling stubs were found in the restored files. Provenance distinguishes intact historical bodies, reconstructed seams, newly authored validation, and unknown checkpoint identity. The corrected WAL seam is now explicitly disclosed.
- Reviewed persisted record tags, layout assertions, generation-bearing references, aligned pending-state stores, reverse locators, descriptor validation, and recovery's durable-clear-before-free ordering against retained consumers. No additional reconstruction-specific layout/ordering mismatch was identified in this review.
- Backend direct-copy bounds and partial-prefix handling match the retained API; ordinary access does not acquire the test crash-image mutex. The new tests do not dynamically exercise a real user-page fault, as provenance states.
- Legacy `cow.rs`/`wal.rs` still retire DRAM-only WAL on SSD completion; they do not implement the final persistent foreground-checkpoint WAL. Legacy CoW also retains spin-lock/wait and completion-generation concerns. These known design gaps prevent claims of final-design crash safety, even if the candidate compiles.
- The 25 restored top-level tests are a disclosed subset; full crash/restart, fixed-inode corruption, batch/migration, and mutation matrices remain missing. Pure-data harness results and rustfmt parsing are not kernel runtime validation. `index.rs:175` also retains an unused legacy descriptor-index builder that derives a slot from SSD backing; retained production recovery correctly uses the physical scan slot instead, so this unused helper must not become a recovery entry point without separate correction.

Disposition: the identified production and test assembly errors were corrected from old evidence and re-reviewed. Preserve this as an explicitly limited reconstruction candidate. Unresolved inherited correctness issues and missing runtime evidence preclude a crash-safe or final-research-kernel claim; no speculative implementation changes were made by this reviewer.
