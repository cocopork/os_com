# Linux / 星绽裸设备性能基线（2026-11-21）

## 目的和口径

实验直接访问guest中的`/dev/vdc`，目标分区不挂载文件系统，用于判断EXT4和
rNVPCe测试中有多少性能差距来自星绽块层/virtio驱动，而不是文件系统。

两侧均使用`psync + direct=1 + iodepth=1/job`，每点约2 GiB、重复3轮。NVMe使用
8 virtqueue，SATA使用1 virtqueue。顺序`write`对应文件系统实验中的append数据
传输模式，`randwrite`对应overwrite访问模式，`randread`对应cold-randread访问模式；
裸设备没有元数据分配、PageCache、writeback、rTIO或文件偏移追加语义。

Linux在32 jobs仍继续扩展。星绽的写路径在20--24 jobs达到峰值，28 jobs开始断崖
下降；读路径在20 jobs后停止扩展，32 jobs降至250.3 MiB/s。因此文件系统高线程
退化不能全部归因于EXT4或rNVPCe，星绽共享块层/virtio/调度路径本身存在瓶颈。

星绽大请求路径明显更接近Linux：512 KiB顺序写差13%，随机写差15%；4 KiB
单线程写则慢约2.4倍。问题主要集中在小请求固定开销和高并发扩展，而不是大请求
数据搬运上限。

明显更严重。256 KiB以上两侧带宽基本接近，主要受SATA介质上限约束。

## 对rNVPCe冷读的含义

同一星绽镜像的NVMe裸随机读上限在256/512/1024 KiB分别为
1345/1575/1992 MiB/s。冷读权威发布消融后的rNVPCe结果为320/326/296 MiB/s，
仅达到裸路径约24%/21%/15%。因此当前rNVPCe大块冷读瓶颈主要仍在文件系统冷读
窗口、逐窗口等待和PageCache/extent路由流程；星绽驱动差距存在，但不能解释主要
性能损失。
