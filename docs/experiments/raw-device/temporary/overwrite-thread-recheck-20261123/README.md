# NVMe 裸设备随机写线程扫描复测（2026-11-23）

## 目的

复测 Linux 与星绽的 NVMe 裸设备 `4 KiB randwrite` thread sweep，确认
`raw-device-baseline-20261121` 中的性能差距是否仍存在。

本轮只复测 overwrite/random-write thread sweep。它足以检验此前讨论的高并发裸设备驱动差距；未重复 append、read、block-size 与 SATA 矩阵。

## 配置

- 设备：`/dev/nvme1n1p2`，未挂载，QEMU 直通原始分区
- fio：`psync`、`direct=1`、`4 KiB randwrite`
- 线程：`1, 4, 8, 12, 16, 20, 24, 28, 32`
- 数据量：每个测试点约 `2 GiB`
- 重复：每点 3 轮
- 虚拟机：64 vCPU、8 GiB、8 virtqueue、8 IOThread
- QEMU 后端：`cache=none,aio=threads`，队列深度 1024
- 星绽：`virtio_blk_direct_submit=on`，rNVPC/rTIO 关闭，性能插桩关闭
- Linux：沿用历史基线的内核和 initramfs

星绽镜像基于 `diag/virtio-direct-submit` 分支的 `740ac3207605c21bb0c8f382e9dff8a8206bc1a0` 加当前未提交的直接提交、IRQ 分布及诊断改动构建。构建时工作区 diff 哈希为：

## 与旧基线的关系

旧基线中，星绽 1/16/32 线程分别为 `45.78/355.61/203.17 MiB/s`；本轮分别为 `104.74/995.83/1184.87 MiB/s`，提升 `2.29x/2.80x/5.83x`。Linux 两轮结果接近，例如 1 线程为 `110.95` 与 `110.89 MiB/s`，32 线程为 `1212.64` 与 `1278.91 MiB/s`。

因此，旧数据不是简单的随机测量错误，而是旧星绽驱动实现的结果。它不能用于评价当前直接提交和 IRQ 分布修复后的驱动。当前星绽在本矩阵中与 Linux 的差距通常为 `1.8%--7.4%`；20 线程点受两侧波动影响，星绽均值高 `8.0%`。
