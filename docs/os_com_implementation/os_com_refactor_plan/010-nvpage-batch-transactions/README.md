# 需求：NVPage 批量事务与 rTIO 区间迁出

日期：2026-10-18。状态：已实现并验证（双副本/区间分配/批量额度/批量回收）；顺序写收益有限，随机写回退，完整文件系统掉电恢复边界仍见009。

实现与测试结果见[010验证报告](../../../experiments/reports/NVPAGE-BATCH-TRANSACTIONS-2026-10-18.md)：307项内核测试通过，24个release A/B点及8个独立诊断点完成。旧版缺口记录保留在下文，实际实现选择见文末。

## 目标

减少逐页目标块分配、目标描述符提交、额度状态提交和回收屏障；候选发现仍使用脏 NVPage 队列，extent 发布延续现有按叶合批。首先适配 rNVPCe soft update；rNVPC WAL 的共享接口适配独立验证，不能混用两个恢复协议。

本需求不负责切换 journal 模式，不因 nojournal 已接入而视为批处理已完成。Nojournal 需求见 ../009-rnvpce-nojournal/README.md。

## 实现前缺口

- SSD 目标仍逐页申请一个块、开一个操作 handle。
- 目标引用和迁出额度标记仍逐页调用 commit_frame，连带重新 persist 4KB 数据内容。
- 最终描述符清除仍逐页 fence；extent 叶更新已经合批，不能重复宣称为新能力。

## 设计一：批量迁出，保持现有恢复语义

这是首先可独立实现、测试和测量的阶段；实现时不同时改变 journal 模式和在途窗口，避免混淆收益来源。

### 连续区间分配

候选页仍由全局脏 NVPage 队列产生，禁止为寻找候选遍历 inode extent 树。按 inode、逻辑块区间整理待分配项；已有 SSD 目标的覆盖写保留原目标，不重复扣容量。

把待分配页形成有界区间，使用现有组级分配器申请多个连续块，而不是固定每次申请一个块。按实际返回长度消费候选；碎片、组边界、事务额度不足时拆分或缩小请求。一次区间或有界事务窗口共享 handle，事务额度按实际元数据修改估算，不能机械地把单块额度无限乘大。

返回区间到 NVPage 的目标映射仍保留逐页身份；逐页枚举是必要的工作，但不应对应逐页事务、完整数据重持久化或独立 fence。

### 分阶段持久化描述符

先建立描述符专用的批量提交接口，避免仅修改迁出字段时调用重新持久化数据的通用接口。具体编码和接口由实现者依据现有描述符布局决定，必须先验证以下恢复契约：

1. 批次内持久引用更新使用 `(slot, allocation_seq)` 校验，lease 覆盖整个更新与发布期间。
2. 不覆盖唯一可恢复的旧描述符后直接宣称原子提交。必须证明当前布局可安全更新，或提供可恢复的新布局及格式版本检查。
3. 可以合并同一依赖阶段内多个页的 persist 和 fence，但不能跨越“分配所有权持久化 → 发布目标引用”或“SSD 数据持久化 → 发布 SSD extent → NVPage 可重用”的边界。
4. 使用已有持久化结构优先；若需要改变持久化格式，显式拒绝不兼容旧池并提供可重复恢复测试，不能静默按新格式解释旧池。保持 WAL-free，不引入操作重放日志冒充 soft update。
5. 失败部分的每一页必须可判断已发布、可重试或需恢复；禁止整批失败后无条件释放所有目标。

extent 发布延续按叶合批，不重新扫描整树；将每页额度阶段更新与每 inode 容量账本更新放入明确的批量依赖协议。描述符清除可按批次写入、统一 fence；只有 fence 成功后才能把对应页加入 free pool。运行时容量通知按批进行。

### 必须保留的顺序

`SSD 分配所有权持久化 → 迁出目标发布 → 数据 BIO → SSD 数据持久化 → NVM extent 发布 SSD 引用 → 额度状态与账本按恢复协议更新 → NV 描述符失效持久化 → 页可复用`

目标发布前仍属私有的块可以回滚；可能形成持久引用的块必须保守保留、恢复判定。SSD I/O 失败不能发布成功的 SSD 映射。陈旧完成不能清除后来复用的页。现有叶级批处理允许成功叶与失败叶独立处理，该语义必须保留。


## 验收

- 连续目标分配次数从页数收敛到区间数；保留碎片退化、部分分配与回滚。
- 数据未改变时不得因描述符更新再次 persist 整个数据页；按协议阶段合并 fence，保留可重复故障恢复证明。
- 覆盖陈旧代际、并发覆盖与 split、部分叶失败、SSD I/O/flush 失败、重复额度归还、批量回收前后的持久化切点。
- 2GiB 总量、64MiB 数据上限，4KiB 随机写/128KiB 顺序写，1/16线程，同模式同环境 A/B；报告分配、persist/fence、叶提交次数和分阶段延迟。
- 第一轮保持128页在途上限，独立评价批处理收益。不得通过关闭 persist 或删除必要设备 flush 制造提升。

## 实现选择与恢复规则（2026-10-18）

- 控制池格式升级到版本4，每项320字节：独立缓存线的选择字、两个各128字节的描述符区域。选择字0表示无有效对象，非零值选择一个副本并随发布递增；旧版池显式拒绝，不能按新stride解释。
- 描述符专用更新先验证整个有界批次的身份/重复槽位，写入所有非活动副本并persist→统一fence，再逐项发布选择字并persist→统一fence。不会重刷未改变的数据页。恢复只认选择字；描述符版本较新但未选中的副本不生效。
- 选择字发布过程中失败可能留下部分已发布页：保留全部可能被引用的目标，并阻止该持久化引擎进一步修改，直到恢复。不能在未确认的选择字上继续翻转副本，覆盖唯一持久有效版本。内容准备阶段失败仍保留旧副本。
- rTIO按inode/连续逻辑区间申请目标，消费实际返回长度；碎片与部分分配可退化。发布前分配失败逐项回滚；分配持久化失败后的整个文件系统孤儿空间恢复仍受009未完成项限制。
- 叶级发布沿用已有实现；成功集合统一提交额度阶段、每inode更新账本和运行时容量；失败叶不回收。批量清除描述符并fence后才把槽位归还free pool，分配池锁以最多32页的有界窗口持有，批末统一通知。
- NVM extent是恢复数据归属的权威。SSD extent已发布但旧NV描述符仍有效时，恢复保留SSD映射并回收冗余NV页；不能根据旧描述符退回NV引用。容量账本从权威图重建，零账本可以不存在。
- `batch_metrics::ENABLED`默认false；独立诊断镜像开启分配、目标发布、数据屏障、叶发布、额度和回收计时以及persist/fence计数。诊断计数不混入release带宽。

## 后续设计：012 orderless migration

[012设计](../012-orderless-migration/README.md)提出取消分配阶段SSD同步，异步提交本批次data与metadata，全部完成后统一flush，再持久发布NVM映射并回收。它以恢复权威及分配核对为前置，尚未实现；本文描述的现有同步顺序和历史验证结论不因此改变。
