# EXT4 功能级 ktest 合并计划

用户要求：合并当前 570 个 EXT4 测试入口，尽可能让一个 ktest 验证一项功能的完整操作。

## 边界与实现决定

- 在现有 `recovery/rnvpc-rebuild` linked worktree 执行，保留已有未提交实现；不修改生产路径、不格式化真实设备、不提交或推送。
- 将同一功能的正常、边界、错误、恢复场景合并到一个命名明确的 ktest。原场景作为普通辅助函数保留，以免把多个夹具强行共享而污染状态，或产生千行巨型函数。
- 不按整个模块粗暴合并。文件读写、truncate、fallocate 各操作、journal capture/commit/checkpoint/replay、目录各操作等分别归组。
- 公共测试辅助函数运行具名场景并记录开始/通过，原来的断言、夹具生命周期、架构 cfg 不变。单个功能失败后不执行该功能剩余场景，其他 ktest 仍由原 runner 继续执行。
- 原测试与新功能入口建立一对一归属映射，570 个原场景必须恰好各归属一次；保留原场景函数体与断言。减少入口数不代表减少覆盖量，也不承诺缩短验证计算量。

## 步骤

1. 保存当前 EXT4 源码、工作树 diff 和完整 570 项清单。先验证覆盖审计能拒绝空映射或遗漏场景。
2. 按功能显式分组，添加仅用于 ktest 的具名场景执行器，移除原场景的注册属性，增加功能级入口。
3. 核对全部原函数体/属性及生产代码未变、映射无遗漏/重复；运行 rustfmt。
4. 在 Docker/QEMU 中运行合并后的 EXT4 和原 PageCache 测试，核对 570 个具名场景实际各执行一次，随后检查完整 kernel ktest。
5. 做一次独立最终代码审查，处理实际缺陷，记录入口数量、场景数量、测试结果和定位方式。
